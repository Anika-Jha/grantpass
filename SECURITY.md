# Security Model

GrantPass is designed around a strict privacy boundary.

## Data that never enters the server

The application does not accept or store:

- Aadhaar number
- applicant name
- date of birth
- address
- photograph
- phone number
- raw Aadhaar QR
- Aadhaar certificate
- raw Aadhaar XML
- IP address as an identity
- device identifier
- wallet address as an identity

## Applicant-side processing

The applicant's Aadhaar QR is processed by the Anon Aadhaar client-side proving flow.

The browser generates a zero-knowledge proof.

The application server receives the proof rather than the underlying Aadhaar identity data.

## Verification boundary

The application server:

1. Retrieves an application-created challenge.
2. Retrieves the application-controlled nullifier seed.
3. Deserializes the submitted ZK proof.
4. Cryptographically verifies the proof.
5. Verifies that the proof signal matches the challenge.
6. Extracts eligibility outputs from the verified proof.
7. Checks the persistent nullifier.
8. Rejects duplicate applications.
9. Records the privacy-preserving application.

The server never trusts a browser-supplied:

- `valid`
- `eligible`
- `isAdult`
- `duplicate`
- `verified`

flag.

## Duplicate prevention

Applications have a database uniqueness constraint:

`cycleId + nullifier`

This provides a persistent one-person-one-application boundary.

The nullifier is generated by the proof system using an application-controlled seed.

The seed is never accepted from the client.

## Application binding

Each application challenge has a unique server-generated signal.

The proof must contain the same signal.

Therefore a proof generated for one application challenge cannot simply be replayed against another challenge.

## Secrets

No credentials, private keys, mnemonics, API keys, or authenticated URLs belong in this repository.

Use `.env.example` only for placeholder configuration.

## Testing

Local testing should use Anon Aadhaar's test Aadhaar mode.

Never upload real Aadhaar documents to a development environment unless the deployment has been reviewed for production use.

## Reporting

If you discover a security issue, please report it privately to the project maintainer rather than publicly exposing sensitive data or exploit material.
